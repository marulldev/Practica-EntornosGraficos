3.a) Diferencias entre los segmentos de código y sus visualizaciones

Línea 1:
<a href="http://www.google.com.ar">Click aquí para ir a Google</a>

Es un enlace simple hacia una página externa. Al hacer clic, el navegador carga la página de Google reemplazando la página actual en la misma ventana/pestaña. El atributo href es obligatorio y define el destino del enlace.

Línea 2:
<a href="http://www.google.com.ar" target="_blank">Click aquí para ir a Google</a>

Es igual al anterior (mismo destino), pero incorpora el atributo target="_blank" (no obligatorio), que indica que el enlace se abrirá en una nueva ventana o pestaña del navegador, sin reemplazar la página actual. Visualmente el texto del enlace se ve igual, pero el comportamiento al hacer clic difiere.

Línea 3:
<a href="http://www.google.com.ar" type="text/html" hreflang="es" charset="utf-8" rel="help">

Este enlace agrega atributos adicionales no obligatorios: type (tipo MIME del recurso destino), hreflang (idioma del recurso destino, en este caso español), charset (codificación de caracteres del recurso destino, obsoleto en HTML5) y rel="help" (indica que el recurso enlazado es de ayuda). Estos atributos no modifican la visualización del enlace en el navegador, solo aportan información adicional (metadatos) para navegadores, buscadores o herramientas de accesibilidad. Además, en este caso no se observa el texto del enlace ni la etiqueta de cierre </a>, por lo que el código está incompleto.

Línea 4:
<a href="#">Click aquí para ir a Google</a>

Aquí el href="#" no apunta a una URL externa sino que es un enlace "vacío" o ancla al inicio de la misma página. A pesar de que el texto dice "ir a Google", al hacer clic el enlace no realiza ninguna navegación real (o como máximo, vuelve al principio del propio documento). Es un ejemplo de una discrepancia entre lo que dice el texto visible y lo que realmente hace el enlace.

Línea 5:
<a href="#arriba">Click aquí para volver arriba</a>

Este es un enlace interno (ancla) que apunta a un punto específico dentro de la misma página, identificado con el nombre "arriba". Al hacer clic, el navegador se desplaza (hace scroll) automáticamente hasta el elemento del documento cuyo id o name coincida con "arriba", sin cargar una nueva página.

Línea 6:
<a name="arriba" id="arriba"></a>

Esta etiqueta no es un enlace que se hace clic, sino el punto de destino (el "ancla") al cual apuntan los enlaces internos como el de la línea 5. No tiene texto visible entre las etiquetas de apertura y cierre, por lo que no se ve reflejado en la página como un enlace clickeable; solo marca una posición del documento. Utiliza dos atributos con el mismo valor ("arriba"): name (forma antigua/obsoleta de nombrar anclas, propia de HTML cuatro) e id (forma moderna equivalente, recomendada en HTML5), ambos no obligatorios pero uno de los dos debe estar presente para que el ancla funcione como destino.

En resumen: las diferencias entre estos segmentos están dadas por el uso de distintos atributos (target, type, hreflang, charset, rel, name, id) que no cambian el texto visible del enlace, pero sí modifican su comportamiento (si abre en la misma ventana o en una nueva, si navega a otra página o se desplaza dentro de la misma) o agregan información adicional no visible directamente en la página.

3.b) Diferencias entre los segmentos de código y sus visualizaciones

Línea 1:
<p><img src="im1.jpg" alt="imagen1" /><a href="http://www.google.com.ar">Click aquí</a></p>

Aquí la imagen y el texto "Click aquí" son dos elementos independientes dentro del mismo párrafo. La imagen no forma parte del enlace <a>, por lo que solo el texto "Click aquí" es clickeable y lleva a Google. Al hacer clic sobre la imagen no ocurre ninguna navegación.

Línea 2:
<p><a href="http://www.google.com.ar"><img src="im1.jpg" alt="imagen1" /></a> Click aquí</p>

En este caso es al revés: la imagen sí está contenida dentro de la etiqueta <a>, por lo que la imagen es clickeable y lleva a Google. Sin embargo, el texto "Click aquí" queda fuera de la etiqueta <a> (después de cerrarla), por lo que ese texto no es un enlace, es solo texto plano sin funcionalidad.

Línea 3:
<p><a href="http://www.google.com.ar"><img src="im1.jpg" alt="imagen1" />Click aquí</a></p>

Aquí tanto la imagen como el texto "Click aquí" están dentro de la misma etiqueta <a>. Esto significa que todo el conjunto (imagen + texto) forma un único enlace: se puede hacer clic tanto sobre la imagen como sobre el texto, y ambos llevan al mismo destino (Google). Visualmente se ve la imagen seguida del texto, ambos como parte del mismo hipervínculo.

Línea 4:
<p><a href="http://www.google.com.ar"><img src="im1.jpg" alt="imagen1" /></a> <a href="http://www.google.com.ar">Click aquí</a></p>

En este último caso hay dos etiquetas <a> distintas (dos enlaces separados), aunque ambas apuntan al mismo destino. La imagen es un enlace independiente y el texto "Click aquí" es otro enlace independiente. Funcionalmente el resultado es similar a la línea 3 (ambos elementos llevan a Google), pero estructuralmente son dos hipervínculos separados en lugar de uno solo que engloba ambos elementos.

En resumen: la diferencia clave entre estos cuatro segmentos está en qué elementos quedan dentro o fuera de la etiqueta <a>:
- Línea 1: solo el texto es enlace (la imagen no lo es).
- Línea 2: solo la imagen es enlace (el texto no lo es).
- Línea 3: imagen y texto forman un único enlace en conjunto.
- Línea 4: imagen y texto son dos enlaces separados, pero con el mismo destino.




3.c) Diferencias entre los segmentos de código y sus visualizaciones

Segmento 1:
<ul>
<li>xxx</li>
<li>yyy</li>
<li>zzz</li>
</ul>

Es una lista no ordenada. La etiqueta <ul> agrupa los elementos <li> y cada uno de ellos se muestra precedido por una viñeta (punto), sin numeración. El orden visual de los ítems no implica secuencia numérica.

Segmento 2:
<ol>
<li>xxx</li>
<li>yyy</li>
<li>zzz</li>
</ol>

Es una lista ordenada. La etiqueta <ol> agrupa los elementos <li>, y el navegador les asigna automáticamente una numeración correlativa (1, 2, 3) según el orden en que aparecen, sin necesidad de indicar el número manualmente.

Segmento 3:
<ol>
<li>xxx</li>
</ol>
<ol>
<li value="2">yyy</li>
</ol>
<ol>
<li value="3">zzz</li>
</ol>

Aquí, en lugar de una única lista con tres elementos, hay tres listas <ol> independientes, cada una con un solo <li>. Como cada <ol> es una lista separada, por defecto cada una reiniciaría su numeración en 1. Para lograr que la numeración continúe como si fuera una sola secuencia (1, 2, 3), se utiliza el atributo value (no obligatorio) en los <li>, que fuerza manualmente el número que debe mostrarse en cada ítem. El resultado visual final es similar al segmento 2 (aparecen los números 1, 2 y 3), pero la estructura del código es distinta: son tres listas separadas en vez de una sola.

Segmento 4:
<blockquote>
<p>1. xxx<br />
2. yyy<br />
3. zzz</p>
</blockquote>

En este caso no se utiliza ninguna lista real (ni <ul> ni <ol>). Los números "1.", "2." y "3." están escritos manualmente como texto plano dentro de un párrafo <p>, y los saltos de línea se generan con la etiqueta <br /> (salto de línea simple, no de párrafo). Además, todo el contenido está dentro de un <blockquote>, que es un elemento usado para citas textuales y que el navegador suele mostrar con sangría (indentado) respecto al margen. Visualmente puede parecerse a una lista numerada, pero semánticamente no lo es: es solo texto con apariencia de lista, indentado como cita.

3.h) Diferencias entre los segmentos de código y sus visualizaciones

Formulario 1:

Este formulario envía sus datos mediante el método POST (method="post") a la página procesar.php, y se abre en una nueva pestaña/ventana debido a target="_blank". Los campos están agrupados dentro de un <fieldset>, que dibuja un recuadro (borde) alrededor de ellos, con el título "LOGIN" mostrado gracias a la etiqueta <legend> (que se posiciona superpuesta sobre el borde superior del recuadro). El campo "Usuario" es de tipo text (input type="text"), por lo que el texto ingresado es visible, y ya viene precargado con el valor "xxx" (atributo value). El campo "Clave" es de tipo password (input type="password"), por lo que el texto ingresado se oculta con puntos o asteriscos, también precargado con "xxx". Al final hay un botón de tipo submit, que al presionarlo envía el formulario.

Formulario 2:

A diferencia del primero, este formulario usa method="get" (los datos se envían visibles en la URL, en lugar de ocultos como con post), y su atributo action="" está vacío (por lo que el formulario se enviaría a la misma página en la que está). Los campos, además, no tienen ningún value predefinido, por lo que aparecen vacíos.

Formulario 3:

<form id="form3" name="form3" action="mailto:xx@xx.com" enctype="text/plain" method="post" target="_blank"> <fieldset> <legend>LOGIN</legend> Usuario: <input type="text" id="usu3" name="usu3" /><br /> Clave: <input type="password" id="clave3" name="clave3" /> </fieldset> <input type="reset" id="boton3" name="boton3" value="Enviar" /> </form>

Este formulario, en lugar de enviar sus datos a un script del servidor, usa action="mailto:xx@xx.com", lo que significa que al enviarse intentará abrir el cliente de correo electrónico predeterminado del usuario para mandar los datos por email a esa dirección. Junto con esto se utiliza el atributo enctype="text/plain" (no obligatorio), que define cómo se codifican los datos enviados, en este caso como texto plano (útil justamente para envíos por mailto). Al igual que el formulario 1, usa <fieldset> y <legend> para agrupar los campos con un recuadro y título "LOGIN", y el campo "Clave" es de tipo password (oculta el texto ingresado), mientras que "Usuario" es tipo text. La diferencia más importante y visualmente relevante está en el botón final: aquí se usa input type="reset" (en lugar de submit), por lo que, aunque el botón diga "Enviar" (por su atributo value="Enviar"), en realidad no envía el formulario, sino que restablece todos los campos a sus valores originales (los vacía o los deja como estaban al cargar la página). Esto representa un caso donde el texto visible del botón no corresponde con su verdadera función.

En resumen, las diferencias principales entre los tres formularios son:

Método de envío: post (formularios 1 y 3, datos ocultos) vs. get (formulario 2, datos visibles en la URL).
Destino: un script del servidor (formularios 1 y 2) vs. una dirección de correo electrónico mediante mailto (formulario 3).
Estructura visual: uso de fieldset y legend para un recuadro con título (formularios 1 y 3) vs. texto plano sin recuadro (formulario 2).
Tipo de campos: password oculta el texto ingresado (formularios 1 y 3 en el campo clave) vs. text que lo muestra visible (formulario 2, en ambos campos).
Tipo de botón: submit, que efectivamente envía el formulario (formularios 1 y 2) vs. reset, que restablece los campos sin enviar nada, a pesar de decir "Enviar" (formulario 3).

- Segmento 1: sin multiple → lista desplegable compacta, selección única (solo una opción posible).
- Segmento 2: con multiple="multiple" → lista expandida con varias opciones visibles a la vez, selección múltiple posible, y el name se ajusta a "lista[]" para reflejar que se envían varios valores al servidor.
